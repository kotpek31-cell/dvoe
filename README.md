# Двое 💞 — общий дневник для пары

Приложение для двух близких людей: сон, настроение, желания, «вопрос дня», кнопка «Думаю о тебе», вода, благодарности, серии дней, оценка дня с автобаллом, недельный отчёт, тепловая карта месяца и виджет с настроением партнёра. Android + iPhone, тёмная тема, русский интерфейс.

<!-- section:architecture -->
## 1. Архитектура

Приложение написано на **Expo SDK 57** (React Native 0.86, TypeScript) с навигацией Expo Router — одна кодовая база собирается в APK для Android и в iOS-приложение через EAS Build. Бэкенд — **Supabase**: Auth (email + пароль), Postgres с Row Level Security, где каждая строка привязана к `pair_id` и видна только двум участникам пары, и Realtime, через который изменения партнёра приходят на экран сразу. Правила живут в базе: создание пары и вход по коду, «вопрос дня» со скрытыми до взаимного ответа ответами, серии дней и защита чужих желаний сделаны SQL-функциями и триггерами. Push-уведомления («Думаю о тебе», ответ на вопрос, исполненное желание) отправляет сама база через `pg_net` в бесплатный Expo Push Service, поэтому отдельный сервер не нужен. Сон на Android определяется собственным Kotlin-модулем по событиям включения и выключения экрана из `UsageStatsManager`, на iPhone — из Apple Health (HealthKit), а в запасе всегда есть кнопки «Иду спать» / «Проснулся». Виджеты: на Android — `react-native-android-widget` (сам берёт свежие данные из Supabase каждые 30 минут), на iOS — официальный `expo-widgets`, которому данные передаёт приложение. Автобалл дня, отчёт недели и тепловая карта считаются на телефоне из общих данных, поэтому оба видят одинаковые цифры.

**Почему такой стек.** Expo даёт один код на обе платформы, бесплатную облачную сборку (EAS) и готовые модули (уведомления, фоновые задачи, виджеты), а свой нативный код добавляется локальным модулем без «выхода» из Expo. Supabase бесплатно закрывает авторизацию, базу, права доступа (RLS) и realtime-синхронизацию — ровно то, что нужно общему дневнику.

## 4. Запуск и установка

### Что понадобится
- Компьютер с **Node.js 22 LTS** и **Git**.
- Бесплатные аккаунты: [supabase.com](https://supabase.com), [expo.dev](https://expo.dev), [Firebase](https://console.firebase.google.com) (push на Android).
- Для iPhone есть два пути: бесплатная **веб-версия** (см. ниже) или **Apple Developer Program** (99 $ в год) — без него Apple не даёт установить собственное приложение через TestFlight, включить push и виджет. Российские карты Apple не принимает.

### Шаги

1. **Создайте проект Supabase.** supabase.com → New project → регион в Европе (например, Stockholm или Frankfurt) → придумайте пароль базы → Create.
2. **Выполните SQL-схему.** SQL Editor → New query → вставьте весь файл `supabase/schema.sql` → Run. Должно появиться «Success. No rows returned». Скрипт можно запускать повторно.
3. **Отключите подтверждение почты.** Authentication → Sign In / Providers → выключите **Confirm email** → Save. Иначе после регистрации нужно подтверждать письмо (бесплатная почта Supabase отправляет всего несколько писем в час).
4. **Скопируйте ключи.** Project Settings → API Keys → **Publishable key** (`sb_publishable_…`), и адрес проекта (кнопка **Connect** или Project Settings → Data API → Project URL).
5. **Подготовьте проект:**
   ```bash
   cd dvoe
   npm install
   npx expo install --fix        # подгонит версии пакетов под Expo SDK 57
   cp .env.example .env          # Windows: copy .env.example .env
   ```
   Впишите в `.env` URL и Publishable key. При желании поменяйте `com.gaster.dvoe` в `app.json` (iOS bundleIdentifier и Android package должны быть уникальными). Затем:
   ```bash
   git init && git add -A && git commit -m "Двое: первая версия"
   npx expo-doctor               # проверка проекта; если попросит — установите пакеты, которые он назовёт
   ```
6. **Быстрая проверка в Expo Go** (без сборки):
   ```bash
   npx expo login
   npx expo start
   ```
   Установите Expo Go из Google Play / App Store, **войдите в тот же аккаунт Expo** (с сентября 2026 это обязательно для iPhone) и отсканируйте QR-код. Зарегистрируйте два аккаунта: первый нажимает «Создать пару», второй вводит код. В Expo Go работает всё, кроме автоопределения сна, виджетов и push на Android — для них нужна сборка (шаги 7–10). Если телефоны в разных сетях: `npx expo start --tunnel`.
7. **Подключите EAS:**
   ```bash
   npm install -g eas-cli
   eas login
   eas init                      # создаст проект на expo.dev и запишет projectId в app.json
   ```
8. **Push на Android (Firebase, бесплатно):**
   - Firebase Console → Add project → Add app → Android → package name `com.gaster.dvoe` → скачайте `google-services.json` в корень проекта.
   - В `app.json` в раздел `"android"` добавьте строку `"googleServicesFile": "./google-services.json"`.
   - Firebase → Project settings → Service accounts → **Generate new private key** (скачается JSON-ключ).
   - `eas credentials -p android` → production → Google Service Account → **Push Notifications (FCM V1)** → загрузите этот JSON.
   - Закоммитьте изменения: `git add -A && git commit -m "firebase"`.
9. **Соберите APK для Android:**
   ```bash
   eas build -p android --profile preview
   ```
   Через 10–30 минут EAS даст ссылку и QR-код. Откройте её на Android, скачайте APK, разрешите установку из этого источника. В приложении: разрешите уведомления → вкладка «Сон» → «Открыть настройки» → включите «Доступ к истории использования» для «Двое».
10. **Установите на iPhone через TestFlight:**
    ```bash
    eas build -p ios --profile production    # войдите Apple ID разработчика; EAS сам создаст сертификаты,
                                             # профили для приложения и виджета, включит HealthKit, App Groups и Push
    eas submit -p ios --latest               # отправит сборку в App Store Connect
    ```
    Когда вопрос появится — ответьте «Yes» на настройку push-уведомлений. Дальше: appstoreconnect.apple.com → «Двое» → TestFlight → дождитесь обработки сборки → Internal Testing → добавьте тестировщика (владельца iPhone нужно сначала пригласить в «Пользователи и доступ») или создайте External Testing с публичной ссылкой (Apple проверяет такую сборку, обычно до суток). На iPhone: приложение TestFlight → установить «Двое» → разрешить уведомления → вкладка «Сон» → «Загрузить сон из „Здоровья“» и выдать доступ. Сборка TestFlight работает 90 дней, потом повторите шаг 10.
    *Альтернатива без TestFlight* (тоже нужен платный аккаунт): `eas device:create` → откройте ссылку на iPhone → `eas build -p ios --profile preview` → установите по ссылке (на iPhone включите «Режим разработчика»).
11. **Добавьте виджет.** Android: долгое нажатие на главном экране → Виджеты → «Двое — партнёр». iPhone: долгое нажатие → «+» → «Двое» → размер.
12. **Обновления.** Изменили код — снова `eas build` (шаги 9–10). Изменили `schema.sql` — снова выполните его в SQL Editor.

### Бесплатный вариант для iPhone: веб-версия
Если платить Apple не хочется, человек с iPhone пользуется «Двое» как сайтом, установленным на экран «Домой». Данные общие с Android-приложением, синхронизация мгновенная. Нет только push-уведомлений, Apple Health и виджета — сон отмечается кнопками «Иду спать» / «Проснулся».

1. Создайте на github.com **публичный** репозиторий, например `dvoe`, и загрузите туда проект (как это сделать с телефона — ниже).
2. В репозитории: Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → вкладка **Variables** → добавьте `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
4. Actions → «Веб-версия» → Run workflow. Через 3–5 минут сайт будет по адресу `https://ваш-логин.github.io/dvoe/`. Дальше он пересобирается сам после каждого изменения в `main`.
5. На iPhone: открыть адрес в Safari → «Поделиться» → «На экран Домой». Иконка «Двое» откроется как обычное приложение.

Проверить веб-версию на компьютере: `npx expo install react-dom react-native-web @expo/metro-runtime`, затем `npx expo start --web`.

### Всё с телефона, без компьютера (GitHub Codespaces)
Самый короткий путь — файл **НАЧНИ_ЗДЕСЬ.md** и скрипт `setup.sh`, который одной командой применяет SQL-схему, записывает ключи, ставит зависимости, отправляет проект в GitHub и собирает APK. Ниже — то же самое по шагам вручную.

Codespaces — бесплатный облачный компьютер с терминалом, который открывается в браузере телефона (на бесплатном плане есть месячный лимит часов, для этого проекта его хватает с запасом). Он находится вне России, поэтому npm и сборка там работают без VPN.

1. На github.com создайте репозиторий (Public, галочка «Add a README»), затем Code → Codespaces → Create codespace. Лучше включить в браузере «Версию для ПК».
2. В панели файлов слева: правый клик (долгое нажатие) → Upload… → выберите `dvoe.zip`.
3. В терминале внизу выполните:
   ```bash
   unzip -q dvoe.zip && cp -r dvoe/. . && rm -rf dvoe dvoe.zip
   cp .env.example .env && code .env      # впишите ключи Supabase и сохраните
   git add -A && git commit -m "Двое" && git push
   ```
   После `git push` веб-версия соберётся сама (см. предыдущий раздел).
4. APK для Android там же:
   ```bash
   npm install && npx expo install --fix
   npm install -g eas-cli && eas login && eas init
   git add -A && git commit -m "eas init" && git push
   eas build -p android --profile preview
   ```
   Ссылку на APK откройте на Android-телефоне. Push на Android дополнительно требует шага 8 (Firebase) — его тоже можно сделать с телефона: `google-services.json` загружается в Codespaces так же, как архив.
5. Когда закончите, остановите Codespace (Code → Codespaces → … → Stop), чтобы не тратить лимит.

### Если вы в России ⚠️
С июня 2025 года российские провайдеры ограничивают соединения с Cloudflare (загружаются только первые ~16 КБ), а `*.supabase.co` работает через Cloudflare. Поэтому без VPN запросы к Supabase могут зависать — приложение покажет «Нет связи с сервером». Варианты:
- **VPN на обоих телефонах** — самый простой путь. Push-уведомления приходят и без VPN: их отправляют серверы Supabase через Expo → Google/Apple.
- **Свой прокси**: VPS, доступный без VPN, + `proxy/Caddyfile`, затем `EXPO_PUBLIC_SUPABASE_URL=https://ваш-домен` и пересборка. VPS платный (обычно от пары сотен рублей в месяц).
- **Self-hosted Supabase** на российском сервере (Docker) — полностью без Cloudflare, но это отдельный сервер.

Сайты Expo, Firebase и Apple на время настройки и сборки тоже иногда требуют VPN на компьютере.

### Частые проблемы
- «Supabase не настроен» — нет файла `.env` или ключи с опечаткой; после правки `.env` перезапустите `npx expo start --clear`.
- «Нет прав на действие» / `permission denied` — SQL-схема выполнена не полностью, запустите её ещё раз.
- Push не приходят — проверьте шаг 8 (Android) или ответ «Yes» на настройку push при iOS-сборке; в Настройках приложения нажмите «Включить / проверить уведомления».
- Сон на Android не определяется — выдан ли «Доступ к истории использования»; ночью до 5:00 автозапись не делается специально; перерыв должен быть от 3 часов.

## 5. Ограничения платформ

| Что | Android | iPhone |
|---|---|---|
| Автоопределение сна | По самому длинному ночному периоду выключенного экрана (`UsageStatsManager`, Android 9+). Разрешение «Доступ к истории использования» пользователь включает вручную. Это эвристика: если лежать без телефона и не спать, это посчитается сном — поэтому есть ручная правка | Сторонние приложения **не могут** узнать, когда гас экран: Screen Time API не отдаёт приложению время использования (его можно лишь показать в изолированном отчёте) и требует спецразрешения Apple. Поэтому сон берётся из Apple Health — данные есть, если спать с Apple Watch, включить «Режим сна»/расписание сна или пользоваться трекером. Иначе — кнопки «Иду спать»/«Проснулся» |
| Разрешения HealthKit | — | iOS не сообщает приложению, дан ли доступ на чтение: при отказе запросы просто пустые, и приложение предлагает кнопки |
| Push-уведомления | Бесплатно через Firebase (FCM). В Expo Go не работают — нужен APK | Нужен Apple Developer Program. В сборке TestFlight работают сразу |
| Виджет | Сам обновляется каждые ≥ 30 минут (минимум Android) и сразу, когда в открытом приложении что-то меняется | `expo-widgets` не ходит в сеть: данные передаёт приложение — при открытии, при изменениях и фоновой задачей, которую iOS запускает на своё усмотрение (обычно раз в несколько часов). Мгновенного обновления нет на обеих платформах |
| Фоновая работа | WorkManager, не чаще раза в 15 минут | BGTaskScheduler на усмотрение системы; если смахнуть приложение из переключателя, фон не работает до следующего запуска |
| Установка | APK напрямую, бесплатно | Только TestFlight или ad hoc, оба требуют платный аккаунт; сборка TestFlight живёт 90 дней |
| Expo Go | Нет автосна, виджета и push | Нет HealthKit и виджета, нужен вход в аккаунт Expo |
| Веб-версия (бесплатно) | Работает, но APK удобнее | Ставится на экран «Домой»; нет push, Apple Health и виджета, сон — кнопками |

## 6. Идеи для следующих версий

1. **Health Connect на Android** — точный сон из браслетов и часов (Mi Band, Galaxy Watch, Pixel Watch) вместо эвристики по экрану, плюс фазы сна.
2. **Мгновенное обновление iOS-виджета** через «тихие» push и Live Activity «партнёр спит» на экране блокировки.
3. **Совместные челленджи и достижения**: «7 дней благодарностей подряд», «неделя без недосыпа», общие цели пары.
4. **Фото дня и голосовые заметки** (Supabase Storage) и «капсула времени», которая откроется через год.
5. **Офлайн-режим** с очередью синхронизации и сквозное шифрование личных заметок.

## Что проверено
- `supabase/schema.sql` прогнан в PostgreSQL 16 с имитацией окружения Supabase: 53 сценария (изоляция пар через RLS, скрытые ответы на вопрос дня, защита чужих желаний, лимит «Думаю о тебе», push-триггеры, серии, выход и возврат в пару, повторный запуск скрипта на заполненной базе) — все прошли.
- TypeScript-проверка в строгом режиме без ошибок; 25 тестов логики (даты и часовые пояса, автобалл, определение сна по экрану и по Apple Health, недельный отчёт) — все прошли.
- Собрать Kotlin/Swift-часть в песочнице было нельзя (нет Android SDK и macOS) — первая настоящая сборка происходит на шагах 9–10 в EAS.
