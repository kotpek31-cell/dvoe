# «Двое» — контекст проекта для Claude

Прочитай этот файл целиком перед любой работой над проектом. Здесь всё, что было выяснено при создании и запуске приложения.

## Что это
Общий дневник для пары. Он (Gaster) — iPhone, она — Android. Всё на русском, тёмная тема.
Функции (с 0.1): пара по инвайт-коду; главная с чибиками на локации; сон; настроение — смесь эмоций на ползунках (сила каждой 0–100, лицо меняется); желания в профиле; «Вопрос дня» (ответы видны после ответа обоих); «Думаю о тебе» (нажать на чибика партнёра → пуш); благодарности; серии (streaks); тепловая карта; оценка дня 1–10 + автооценка (сон 0.35, настроение 0.4, заполненность 0.25) и итоги; виджеты. Воды больше нет (таблица water_logs осталась, но не используется).

## Стек
Expo SDK 57 (RN 0.86, React 19.2), Expo Router (группа `(tabs)`: home, mood, sleep, us, stats, profile — своя плавающая панель `TabBar`; плюс sign-in, pair, onboarding, day-score, questions, settings), supabase-js v2, EAS Build. Графика — react-native-svg (лица, чибики, локация), анимации — RN Animated (native driver), шрифты Nunito + Unbounded (@expo-google-fonts).
Платформенные файлы: `*.web.ts`, `*.ios.ts`, `*.android.tsx` — нативные модули не должны попадать в веб-бандл.
- Сон Android: локальный модуль `modules/screen-sleep` (Kotlin, UsageStatsManager, события 15/16/26/27). Экран включён ≤3 мин — склеивается; сон = самый длинный интервал выключенного экрана ≥3 ч, пересекающий 20:00–12:00. Нужен доступ «История использования».
- Сон iPhone: на сайте только кнопки «Иду спать»/«Проснулся». HealthKit (@kingstinct/react-native-healthkit) есть в коде, но работает только в нативной iOS-сборке (нужен Apple Developer $99 — пользователь отказался).
- Виджеты: Android — react-native-android-widget (сам тянет данные каждые 30 мин); iOS — expo-widgets (не используется, нет iOS-сборки).
- Фон: expo-background-task. Диалоги на вебе: `src/lib/dialogs.ts` (Alert в RN-web не работает).
- БД: `supabase/schema.sql` — идемпотентный, строгий RLS, явные GRANT; функции create_pair, join_pair, leave_pair, daily_question, answered_days, pair_streaks, partner_snapshot, save_web_push, delete_web_push; пуши из триггеров (nudges, ответы, новые и исполненные желания) через `notify_partner`: pg_net → Expo Push API (Android) и pg_net → Edge Function `push` (web push). Триггер on_auth_user_created создаёт профиль.
- Web push: Edge Function `supabase/functions/push/index.ts` (шифрование RFC 8291 + VAPID на WebCrypto, без библиотек). Ключи VAPID и секрет `push_secret` лежат в `private.app_config` (схема private не видна через API); функция читает их ключом сервера (`SUPABASE_SECRET_KEYS`/`SUPABASE_SERVICE_ROLE_KEY`) через RPC `push_config` и сама создаёт ключи VAPID при первом запуске. Секреты вручную задавать не нужно. У функции должна быть ВЫКЛЮЧЕНА проверка JWT. Адреса подписок — только Apple/Google/Mozilla/Microsoft.
- Push Android: `google-services.json` лежит в корне Codespace (в .gitignore, но НЕ в .easignore → попадает в EAS Build); `app.config.js` подключает его, если файл есть. Ключ FCM V1 (service account) загружается на expo.dev → Credentials.
- Профиль: `profiles.chibi` (JSON, сейчас `{"kind": "boy"|"girl"|"nb"}`); настроение: `mood_entries.emotions` (JSON {эмоция: 0–100}), в emotion/intensity пишется главная эмоция для старых версий.

## Как пользователь работает (важно!)
- Всё делает **с iPhone**. В терминал Codespace **вставка не работает** — всё печатает руками, iOS-автозамена портит текст. Давай команды максимально короткими; длинные значения — через веб-интерфейсы (GitHub-редактор, Supabase SQL Editor), там вставка работает.
- Обновление кода: архив → загрузить в Codespace → распаковать → `git add -A && git commit -m … && git push` → сайт обновится сам; APK: `git pull` + `eas build -p android --profile preview`, ставить поверх (данные в Supabase сохраняются). С 0.1 в архиве есть `update.sh`, который делает всё это сам (включая удаление старых файлов и установку новых пакетов): `unzip -q dvoe.zip && bash dvoe/update.sh`.
- Изменения схемы БД — SQL для Supabase → SQL Editor → Run.
- После работы останавливать Codespace (github.com/codespaces → … → Stop).
- GitHub Pages кэширует до 10 минут — для проверки открывать `?v=N`.
- Из России Supabase может резаться; у пользователя VPN INCY в глобальном режиме — работает.
- `eas login` через браузер с телефона не работает (callback на localhost) — поэтому EXPO_TOKEN.
- Пользователь считает лимиты: отвечать кратко, по-русски, по шагам, по одному действию.

## Обновление 0.1 — требования пользователя
1. Пуш-уведомления (в т.ч. «Думаю о тебе» → уведомление партнёру). Android — Firebase/FCM; iPhone-сайт — Web Push (только PWA на экране «Домой», iOS 16.4+; отправка через Supabase Edge Function с VAPID, pg_net сам не умеет шифровать web push).
2. Отслеживание сна: Android сам предлагает дать доступ (онбординг/баннер); iPhone остаётся ручным.
3. Дизайн с анимациями: аврора-фон + стеклянные карточки + бенто + микровзаимодействия (сердечки, конфетти, переворот карты, пружинящие кнопки).
4. Чибики людей с большой кастомизацией (причёски, лица, одежда, цвета) — рисовать своими векторными (SVG) слоями, без чужих персонажей; настройки хранить в профиле (JSON).
5. Убрать систему воды (из UI и автооценки; таблицу можно оставить).
6. Желания переделать: у пользователя есть профиль, туда можно добавить «желание на сегодня»; показывать текущее и исполненные.
7. Приложение должно выглядеть живым — постоянное движение (с учётом производительности и «уменьшить движение»).
8. Все функции разложить по вкладкам и сделать интересными. Настроение: ряд ползунков — у каждой эмоции своё лицо-эмодзи, чем дальше тянешь, тем выраженнее эмоция на лице (SVG-морфинг). Модель данных: набор интенсивностей эмоций вместо одной эмоции.
9. Главный экран — только чибики, гуляющие по красочным локациям; локация меняется каждый час. Вопрос дня и прочее второстепенное — не на главной.
10. Итоги компактнее и информативнее: средний сон, настроение 0–10, главная эмоция за день/неделю/месяц, график лучших дней, сколько желаний исполнено из всех.

Оценка рисков (обсуждено): п.4 и п.9 — самые объёмные (нужна векторная графика; качество «мило и стилизованно», не уровень профессионального художника). Рекомендовано разбить: 0.1 — всё кроме чибиков и локаций (или простая версия чибиков), 0.2 — полноценные чибики, кастомизация и локации.

### Решения по 0.1 (приняты пользователем)
- Разбиваем: **0.1** — пуши, сон (запрос доступа), удаление воды, желания + профиль, ползунки настроения с лицами, компактные итоги, новый дизайн с анимациями, вкладки, простые чибики на главной; **0.2** — полная кастомизация чибиков и красивые локации (6–8 шт., смена каждый час + вариации по времени суток).
- Вкладки: «Главная» (только чибики), «Настроение», «Сон», «Мы» (вопрос дня, благодарности, оценка дня), «Итоги», «Профиль» (желания, настройка чибика, настройки).
- «Думаю о тебе» — по нажатию на чибика партнёра. Чибик партнёра спит, когда партнёр спит, и отражает его настроение.
- Android-виджет перерисовать под новый стиль.
- Анимации лёгкие (Safari на iPhone, слабые Android), учитывать «уменьшить движение». Чибики — оригинальные, без сходства с известными персонажами.
- Чибики в 0.1 — только стандартные, без вариантов причёсок и цветов. Большая кастомизация (причёски, глаза, рост и т. д.) — позже. Рисунок слоями, чтобы её было куда добавить.
- Порядок работы: сначала макет главной и настроения → согласование → код.
- Макет 0.1 сделан (артефакт Design «Двое 0.1 — макет»: главная день/ночь, настроение, лица эмоций, чибики). Лица — один параметрический генератор (0 → 100), он же рисует лицо чибика.
- Стандартных чибиков три: мальчик, девочка и небинарный (по просьбе пользователя — чтобы не было проблем с сообществами). Пока человек не выбрал — показывается небинарный.
