# «Двое» — контекст для Claude

Читай целиком перед любой работой. Здесь всё, что нужно знать о проекте и о том, как работать с пользователем.

## 1. Что это
Общий дневник для пары. Gaster — iPhone (сайт на экране «Домой»), партнёрша — Android (APK). Всё на русском, тёмная тема.
Цель — публичный продукт (Google Play / RuStore / App Store в будущем): решения принимать с расчётом на это — безопасность, удаление аккаунта, политика конфиденциальности, 152-ФЗ, доступность Supabase из РФ.

**Версия 0.1.1 (выпущена 1 октября 2026):** вкладки Главная / Настроение / Сон / Мы / Итоги / Профиль; онбординг (чибик → уведомления → доступ к сну на Android); главная «Луг у озера» (день/вечер/ночь), чибики гуляют, спят, когда человек спит, показывают настроение; «Думаю о тебе» — нажать на чибика партнёра; настроение — ползунки-смесь эмоций с лицами (0–100); желания в профиле (новые + исполненные, пуш о новом желании); вопрос дня, благодарности, оценка дня; итоги; аврора + стекло + анимации; пуши на iPhone (Web Push) и Android (FCM); Android-виджет с лицом настроения. Воды больше нет (таблица water_logs осталась, не используется). Чибики: мальчик / девочка / небинарный (по умолчанию небинарный).

## 3. Стек и устройство
Expo SDK 57 (RN 0.86, React 19.2), Expo Router, supabase-js v2, react-native-svg, RN Animated, шрифты Nunito + Unbounded (@expo-google-fonts). Платформенные файлы `*.web.ts` / `*.android.tsx` / `*.ios.ts` — нативное не должно попадать в веб-бандл.
- Вкладки: `app/(tabs)/` home, mood, sleep, us, stats, profile + своя панель `src/components/TabBar.tsx`. Прочие экраны: sign-in, pair, onboarding, day-score, questions, settings.
- Графика: `src/lib/face.ts` — параметрический генератор лиц (эмоция 0→100), он же рисует лицо чибика и виджета. `src/components/Chibi.tsx` — чибик слоями SVG (волосы сзади, ноги, тело, руки, голова, лицо, чёлка), анимация слоёв трансформациями. `src/lib/chibi.ts` — описания видов. `src/components/scene/Meadow.tsx` — локация.
- Сон Android: `modules/screen-sleep` (Kotlin, UsageStatsManager). iPhone — кнопки «Иду спать / Проснулся».
- БД: `supabase/schema.sql` — идемпотентный, строгий RLS, явные GRANT. `profiles.chibi` (jsonb, `{"kind": ...}` — сюда же пойдёт гардероб), `mood_entries.emotions` (jsonb {эмоция: 0–100}; в emotion/intensity — главная эмоция для старых версий).
- Пуши: `notify_partner` в базе → pg_net → Expo Push API (Android) и → Edge Function `push` (Web Push, RFC 8291 + VAPID на WebCrypto). Ключи VAPID и `push_secret` в `private.app_config`, функция читает их ключом сервера и сама создаёт VAPID при первом запуске. У функции ВЫКЛЮЧЕНА проверка JWT. Адреса подписок — только Apple/Google/Mozilla/Microsoft.
- `src/lib/focus.ts` — `useScreenFocused` (анимации на скрытых экранах стоят).

**Грабли (уже наступали):**
- В RN-web `Animated.loop` с одной анимацией и `useNativeDriver: true` проигрывается ОДИН раз → всегда `useNativeDriver: nativeDriver` из `src/lib/motion.ts`.
- Неактивные вкладки в вебе навигатор может не прятать → каждая вкладка непрозрачная со своей авророй (`Screen tabs`), прозрачных сцен не делать.
- `npx expo install` с `app.config.js` пишет «Cannot automatically write to dynamic config» и выходит с ошибкой — в скриптах не использовать с `set -e` без `|| true`.
- В Supabase SQL Editor кнопка «Run selected» выполняет только выделенное; предупреждение про RLS для нашего скрипта — «Run without RLS» (RLS включается в самом скрипте).
- В песочнице Claude npm может быть закрыт — тогда настоящий tsc/сборка только в EAS/Actions; проверять логи через коннектор Expo.

## 5. Пользователь и как он работает
- Работает с **iPhone**; компьютер есть, но не всегда. Задачи, которые удобнее на компе (регистрации с документами, сложная настройка), помечай «на компе» и предлагай отложить.
- В терминал Codespace вставка не работает — команды максимально короткие; длинное — через веб-интерфейсы (GitHub, Supabase), там вставка работает.
- Отвечать: по-русски, кратко, по шагам, по одному действию за раз. Ссылки — прямые.
- Есть самозанятость (для оплаты через ЮKassa).
- Лимиты важны: новый чат на каждое обновление/этап; длинный чат → итоги в файл и новый чат.

## 6. Правила работы Claude (предлагай сам — пользователь может не помнить)
- **Большая задача** (новая версия, функция): сначала интервью (10–25 вопросов) → ТЗ/план → при визуальном — макет → «ок» пользователя → только потом код. На каждой границе этапа остановись: «приступаю к …?» и подскажи уровень рассуждений: интервью — high, ТЗ — максимум, макет и разработка — high, установка/инструкции — medium. Менять уровень только на границах этапов.
- **Мелкие задачи** (поправить текст, баг по скриншоту) — делать сразу, без лишних вопросов.
- **Перед работой** скажи, как будешь проверять результат и что пользователю придётся проверить на телефоне.
- **5+ подзадач** — веди чек-лист, сверься с ним перед «готово».
- **Много независимых частей** — предложи субагентов, предупреди, что это дороже по лимиту.
- **Процесс повторился второй раз** (выпуск версии, SQL, APK) — предложи собрать скилл и включить туда прошлые ошибки.
- **Чат стал длинным** или пошли инструкции вместо разработки — предложи сохранить итоги в файл, открыть новый чат и снизить уровень рассуждений.
- **Необратимое — только после явного «да»:** удаление/изменение данных в базе (в т.ч. через коннектор Supabase), смена пакета/projectId, работа с секретами, push в `main` (= живой сайт), запуск платной сборки/операции.
- Ответ дан — считай закрытым, не возвращайся без просьбы. Время важно: не трать его на то, чего можно избежать.
- **В конце каждой версии** обнови этот файл: что сделано, что изменилось, новые грабли, следующий шаг. Напомни об этом сам.

## 7. Как выпускать обновление
1. Код: облачная сессия на `dvoe` → изменения в ветке → после «ок» в `main` (сайт обновится сам). Без облачной сессии — архив + `update.sh` в Codespace.
2. База: изменения только в `supabase/schema.sql` (идемпотентно), применять через коннектор Supabase после «да» или через SQL Editor.
3. Edge Function `push`: через коннектор Supabase (deploy) с выключенной проверкой JWT.
4. APK: `eas build -p android --profile preview` в Codespace (или через Expo-коннектор, когда google-services.json переедет в EAS env var). Ссылка на APK — из списка сборок.
5. Проверка на телефонах обоих → баги → обновить этот файл.

## 8. План
### 0.2 — «Гардероб и способности» (сейчас)
Системы целиком + стартовый контент (по 3–4 вещи на категорию, 3–4 локации):
1. **Инвентарь** с сортировкой (по категории, редкости — редкость заложить в данные, показывать позже) — всё надеваемое: одежда, предметы, способности.
2. **Гардероб** — экран из профиля рядом с чибиком. Категории: шляпы, причёски, глаза, верх, низ, обувь, аксессуары (предметы в руках), цвета (система перекраски — 10 цветов). Надетое видят все.
3. **Улучшенные чибики** — переработать базу под гардероб (слои под одежду), детальнее и живее; сохранить стиль.
4. **Способности** (кнопка-суперспособность на главной, надеваются в инвентаре):
   - «Мог» (платная): твой чибик подбегает к партнёру, кинематографичная сцена — затемнение, черепа/скулы, звук «мог-мог-мог» (голос записывает пользователь) + напряжённый звук, удар, партнёр падает на несколько секунд. Пока оплата не подключена — выдаётся секретным кодом.
   - «Объятия» (бесплатная).
   - Партнёр видит сцену у себя (realtime) — продумать в ТЗ.
5. **Локации**: в итоге 10, выбор вручную, у каждой день/вечер/ночь по реальному времени. В будущем — открываются за парные мини-игры.
6. **Секретные коды** — отдельный раздел. Сами коды НИКОГДА не писать в репозиторий (он публичный) — ни в код, ни в этот файл, ни в коммиты. Пользователь называет их в чате, они сразу уходят в таблицу базы; проверка только на сервере. Одноразовые на аккаунт. Первые три кода дают:
   - набор художника;
   - крылья ангела и нимб (анимация парения над землёй);
   - бандитская бандана и узи (оставляем; если магазины поднимут рейтинг — заменим).
   Отдельный код выдаёт способность «Мог», пока не подключена оплата.
7. **Нижняя панель**: активная вкладка — мягкая скруглённая подсветка или отдельные кнопки-островки (показать оба варианта на макете).
8. **Интерактив главной** (начальный): реакции чибиков на касания, взаимодействие двух чибиков — на усмотрение, но лёгкое.
9. **Новая иконка приложения** (и сплэш, иконка уведомлений, фавикон сайта): нынешние два круга почти совпадают с иконкой приложения You&Me — до публикации обязательно заменить на своё, уникальное и запоминающееся. На макете нарисовать варианты по идеям (пользователь выберет):
   - «Две щёчки» — две чибиковые головы прижались щеками (голубая и розовая), румянец на стыке;
   - «Одно лицо на двоих» — круглая мордашка, один глаз голубой, другой розовый;
   - «Д с характером» — буква «Д», ножки — два маленьких чибика, сверху сердечко;
   - «Ладошки» — две лапки чибиков тянутся друг к другу, между ними искорка;
   - «Сонный и бодрый» — одна голова спит (колпак, «Z»), другая подмигивает.
   Везде: тёмный фон с лёгкой авророй, акцент `#FF6B8A` + сиреневый, читается в маленьком размере, не похоже на пересекающиеся круги.
10. **Комната разработчиков** — скрытый экран, виден только аккаунтам с ролью «разработчик» (роли в базе, проверка на сервере; разработчиков сколько угодно, главный — Gaster, он добавляет и убирает). Внутри: выдать любой предмет/способность себе или другому; создать секретный код и видеть, кто его ввёл; запустить способность «вхолостую»; переключать время суток и локацию для проверки; общая статистика (сколько пар, активных).
