# «Двое» — ГЛАВНЫЙ РЕЗЕРВНЫЙ ФАЙЛ

Проект «Живая рука». Обновлено: 2 октября 2026.
С этим файлом и резервной копией проект можно восстановить и продолжить **без Claude** — с любым другим помощником или разработчиком.

В этом файле нет паролей, ключей и секретных кодов. Он лежит в публичном репозитории (`docs/ГЛАВНЫЙ_РЕЗЕРВНЫЙ_ФАЙЛ.md`) — личного сюда не писать.

---

## 1. Главное за минуту

- Приложение, сайт и база **не зависят от Claude**. Если доступ к Claude пропадёт, у тебя и партнёрши всё продолжит работать.
- От Claude зависит только разработка: чаты, документы ТЗ и макеты. Тексты ТЗ лежат в репозитории (`docs/TZ_*.md`), итоги этапов — в `docs/PROGRESS_*.md`.
- Весь код и вся история — на GitHub. **Автоматическая копия** всех веток — в приватном репозитории `kotpek31-cell/dvoe-backup` (обновляется при каждом изменении, см. раздел 6).
- Данные (записи дневника, вещи, роли, отпечатки кодов) — в Supabase. **Автоматическая копия** раз в сутки, последние 14 — в том же приватном репозитории, ветка `db-dumps`.

## 6. Автоматическая копия (`backup.yml`)

| Что | Когда | Куда |
| --- | --- | --- |
| Все ветки и теги | при каждом push в любую ветку, где уже есть `backup.yml`, и раз в сутки | `dvoe-backup`, те же имена веток |
| База: схемы `public` и `private` (pg_dump, сжатый .sql.gz) | раз в сутки в 03:23 по Москве и по кнопке Run workflow | `dvoe-backup`, ветка `db-dumps`, последние 14 файлов |

- `main` копируется только вперёд: если его историю перепишут, копия не затрётся, а запуск станет красным — это сигнал разобраться.
- Удалённые ветки в копии остаются.
- Аккаунты (схема `auth`: почты, пароли) в копию не входят — только `public` и `private`.
- Секреты в репозитории `dvoe` (Settings → Secrets and variables → Actions): `BACKUP_TOKEN`, `SUPABASE_DB_URL`. В логах Actions их нет, дамп с личными данными уходит только в приватный репозиторий.
- В `dvoe-backup` выключены Actions (иначе скопированные workflow начнут там запускаться).
- Проверка: `github.com/kotpek31-cell/dvoe/actions/workflows/backup.yml` — последний запуск зелёный.

**Вручную, на компе** (если автоматика не работает), нужен PostgreSQL 17 и строка подключения Session pooler из Supabase (кнопка Connect):

```
pg_dump "СТРОКА_ПОДКЛЮЧЕНИЯ" -n public -n private --no-owner | gzip > dvoe_данные.sql.gz
```

В файле личные записи и отпечатки кодов — никому не отправлять и не класть в публичный репозиторий.

## 7. Как восстановить

### Код пропал с GitHub или закрыт доступ к репозиторию `dvoe`

1. Возьми код из `dvoe-backup` (там все ветки) или из `dvoe-вся-история.bundle`: `git clone dvoe-вся-история.bundle dvoe`, затем `cd dvoe` и `git checkout main`.
2. Создай новый репозиторий на GitHub и отправь туда: `git remote set-url origin НОВЫЙ_АДРЕС`, затем `git push --all`
3. В репозитории включи Settings → Pages → Source: GitHub Actions. Сайт соберётся сам.
4. Если адрес сайта изменился, поправь `vapid_subject` в `private.app_config` и адрес в `CLAUDE.md`.
5. Если поменялось имя репозитория — поправь проверку `github.repository` в `backup.yml` и заведи секреты заново.

### База пропала

1. Создай новый проект Supabase.
2. В SQL Editor выполни по очереди: `supabase/schema.sql`, `supabase/catalog.sql`, все `supabase/patch_*.sql`.
3. Данные: скачай последний файл из ветки `db-dumps` в `dvoe-backup`, на компе: `gunzip -c ФАЙЛ.sql.gz | psql "СТРОКА_ПОДКЛЮЧЕНИЯ"` (дамп содержит и структуру — на чистую базу его можно загрузить вместо шага 2; аккаунты пользователей нужно будет создать заново).
4. Разверни функцию `push` из `supabase/functions/push/index.ts` с выключенной проверкой JWT.
5. Впиши новый адрес и ключ проекта в `.env` и в переменные репозитория, поправь `push_url` в `private.app_config`, обнови секрет `SUPABASE_DB_URL`.
6. Заново заведи секретные коды и назначь себя владельцем (по ID из настроек).

### Нужен новый APK

- Через сайт expo.dev: проект `dvoe` → Builds → новый билд, профиль `preview`, ветка `main`.
- Или в Codespace: `eas build -p android --profile preview`.
- Обновление без нового APK: `eas update --channel preview`.

## 8. Как продолжить работу без Claude

Любому помощнику или разработчику дай три вещи: репозиторий (или копию из `dvoe-backup`), `CLAUDE.md` и последний `docs/PROGRESS_*.md` с `docs/TZ_*.md`. Первое сообщение:

```
Это проект «Двое» (Expo + Supabase). Прочитай CLAUDE.md, docs/PROGRESS_0.2.2.md и docs/TZ_0.2.2.md — там всё о проекте, правила работы и текущее состояние. Продолжаем с этапа, который указан в PROGRESS как следующий.
```

Доступы к Supabase и Expo у другого помощника придётся настроить заново или делать эти шаги руками по разделу 7 в `CLAUDE.md`.

## 9. Порядок «Живая рука»: что делать после каждого этапа

Сессия разработки делает сама (правило записано в `CLAUDE.md`, раздел 6):

1. Обновляет `docs/PROGRESS_*.md` и этот файл: дата, состояние версий и веток, что изменилось в инфраструктуре и в шагах восстановления.
2. Сохраняет в `docs/` полный текст ТЗ текущей версии и ссылки на макеты.
3. Отправляет всё в GitHub.
4. Проверяет, что последний запуск `backup.yml` прошёл успешно.
5. Присылает тебе этот файл.

Ты делаешь:

1. Сохраняешь присланный файл в папку «Живая рука».
2. Раз в месяц и перед выпуском — заглядываешь в `dvoe-backup`: есть свежие ветки и файлы в `db-dumps`.
3. Следишь за сроком `BACKUP_TOKEN` (раздел 4).
